# 26.0.3 交互回归修订（2026-08-30）

## 最新追加：视觉更新开关、分段白边、预览配色与外观窗口复开

- 「设置 → 外观与背景」新增“不可见时暂停视觉更新”，默认开启。关闭后继续更新已挂载视图的数据/计时；不预建未进入页面，不阻止正常销毁，不改变音频播放，不覆盖系统减少动画及真正暂停/退出状态。不是强迫不可见窗口持续绘图的开关。
- 分段按钮内部实际高度与外部边框一致，修复最小44px容器里40px按钮留下的4px白边；图标和文字作为一个整体居中，对称留白，保留Material状态、焦点、语义和点击区域。
- 任务栏自绘歌曲预览的歌曲名、艺术家、专辑与品牌文字统一跟随封面/主题主色；低对比配色仅调整明暗保证可读性，字体及回退链保持不变。Windows系统提供的窗口标题和按钮提示不使用私有接口强行着色。
- 歌词外观窗口仍然完全独立于歌词外框。正常关闭前确认最后编辑，之后最多保留一个隐藏窗口120秒以供快速复开；隐藏暂停ticker/焦点/编辑计时器和主题通信，超时或退出回收，不在启动时预热。首次打开减少一次跨引擎握手并显示加载反馈，但仍需要初始化引擎，不声称所有机器瞬开。
- 复开先更新会话、最新字体/四语/主题并绘制新帧再显示；陈旧回包不污染新会话。窗口本身采用16逻辑像素原生圆角，与内容裁剪一致，随DPI更新，无需改变歌词父窗口几何或透明度。

## 前轮追加：独立歌词外观窗口、视图与托盘模糊

- 用户复测确认旧外观路由方案仍有歌词外框闪烁；因此下文关于“临时扩容/恢复”的旧实现不再是当前行为。外观面板改为按需创建的独立、受歌词窗口拥有的原生窗口，首次画面完成后才显示；关闭销毁其渲染引擎，后台不保留第二套动画或播放器。打开/关闭不调整歌词窗口尺寸、最小尺寸、可见性或透明度。
- 外观面板复用原选项组件；通过带会话标识的字段补丁修改原有外观模型，连续滑动合并提交。没有第二套播放、文件读取或保存逻辑。关闭先确认末次补丁；发送失败保留重试，原模型的磁盘保存错误另行同步，不能将传输确认误认为落盘成功。主题、字体、四语、布局/保存错误实时同步，过期会话不能影响新面板。
- 音乐分栏表头采用圆角浅色容器、主题强调色与轻分隔线，列位置保持与歌曲行一致。列表/网格、排序方向和两项设置优先外显为共用分段控件；按真实字体和系统字号测量，放不下时使用菜单，同一选择不会重复执行。工具提示恢复完整字体和回退字体继承。
- 歌单及子歌单新增“圆形”视图：大圆封面、居中名称和详情、紧邻的播放与更多操作。三种视图共用已有排序、重排、选取和菜单逻辑；新偏好兼容原列表/网格设置。窄窗口或大字号下的详情标题独立限高滚动，歌曲列表继续有可用空间。
- 「设置 → 桌面与快捷键」新增托盘菜单模糊强度（0–24，默认0）。打开自有菜单时仅采样最终菜单矩形一次并执行真实高斯模糊，菜单存在期间复用内存图，不持续截图、不保存截图文件；关闭释放像素与GDI资源。系统关闭透明效果、节能、高对比度、采样失败或超过像素预算时回退实色，不使用私有任务栏接口。
- 本次所有新增图标/标签/滑条提示沿用主题与完整字体继承；包括圆形视图、分段选中/未选中/禁用状态、四语和200%字号回归。仍不启动安装版进行GUI视觉验收，不修改用户音乐或原有配置。

## 前轮追加：界面语言、布局与隐藏渲染

- 界面语言位于「设置 → 外观与背景」，可选中文、English、日本語、한국어。共享文案表明确区分界面文本与歌曲/歌词/文件数据；主应用、桌面歌词外观和原生托盘菜单同步切换。180ms轻淡入沿用原组件树，不重建播放器、路由、编辑器或滚动状态；系统减少动画时直接切换。Windows自身文件对话框/高对比度菜单仍遵循系统无障碍策略。
- 前轮桌面歌词通过保持歌词区域、临时扩容和恢复来承载外观路由。用户再次复测发现仍闪烁，已由上面的独立窗口替代；旧几何回归不能作为真实桌面合成器无闪烁的证明。
- 托盘菜单加载主播放器同源字体文件，私有字体注册与DPI字号缓存具有配对清理；自定义字体不可用时安全回退，系统高对比度菜单不强行覆盖系统字体。
- 文件夹采用图标卡片、目录名称和父路径分层；歌单默认紧凑排列，播放/菜单靠近对应项目。「外观与背景 → 音乐列表样式」可选择经典或歌名/作曲家/专辑分栏；按实际文本缩放决定宽度，空间不足自动回退经典布局。作曲家沿用已认可的参与艺术家回退，未改音乐标签。
- 界面语言、列表样式、紧凑歌单、侧栏/窗口布局、桌面歌词字体与单行样式集中至「外观与背景」。后台播放、系统托盘、任务栏缩略图与快捷键保留在「桌面与快捷键」。
- 歌词详情本就按进入路由创建，未进入时不创建完整动画。补齐已隐藏歌词视图的进度订阅/手动滚动计时器暂停，以及窗口隐藏时的频谱订阅暂停；恢复读取最新播放位置一次并保留文字、排版和封面缓存。未通过强制释放缓存换取纸面内存下降，也不增加无实际必要的开关。
- 本轮继续不启动安装版或GUI视觉验收；所有结论来自代码、widget交互布局、原生无窗口字体/策略检查及构建。跨Win10/11真机、特殊显卡/字体和长时间播放不冒称全面认证。

## 前轮实装范围（外观路由已被替代）

- 桌面歌词外观使用独立 DialogRoute。旧 MenuAnchor 的尺寸变化关闭行为会与原生窗口展开形成开关循环；新路由先建立、再调整窗口，退出动画完成后恢复原横排/竖排/单行边界。控制按钮卸载、迟到尺寸响应、连续点击、缩放和保存错误均有回归测试。
- 联网信息编辑的搜索/字段选择区与候选结果各自滚动，确认/取消保持固定；重新搜索保留勾选，旧搜索不能覆盖新结果，选中仅返回编辑器，不自动写原文件。
- 主应用弹窗采用共享居中标题，带关闭按钮/开关时使用左右平衡槽。表单、说明和列表仍左对齐；顶部歌词短句居中，长句保留完整 Unicode 单行与现有横向跟随滚动。

- 修复桌面歌词启动等待期间丢失封面主题及系统深浅色的竞态，进程就绪时读取最新完整主题。新增文字、图标、滑条等使用现有主题；用户主动选定固定歌词色为显式例外。

## 桌面歌词单行模式

入口：设置 → 外观与背景 → 桌面歌词显示，或桌面歌词 → 歌词外观。

这是正常置顶窗口，不是向 Explorer 注入或将窗口设为任务栏子窗口。按当前屏幕工作区底边停靠，窗口宽度不超出该屏幕工作区；底部任务栏时显示在其上方，侧边/顶部任务栏时仍放在工作区底部。先在目标屏幕放好悬浮歌词再开启模式，即可选择所在屏幕。

几何依据使用公开的 [MONITORINFO.rcWork](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfo) 和最近显示器策略；自动隐藏任务栏通过只读 [ABM_GETAUTOHIDEBAREX](https://learn.microsoft.com/en-us/windows/win32/shell/abm-getautohidebarex) 查询所在屏幕的四边 appbar 尺寸并避让，不依赖 `Shell_TrayWnd` 私有布局或轮询置顶。查询失败回退普通工作区，不修改系统任务栏。响应显示器/DPI/工作区变化与拖动完成事件；重复几何请求不会重复调整窗口。查询期间发生DPI变化会重新读取，并保留最后一次工作区事件；窗口绑定销毁使迟到的几何写入失效。

常规宽度保留上一首、播放/暂停、下一首、外观、恢复悬浮；较窄时收起上一首/下一首，让歌词保留空间。所有控制都限制在窗口内部，极小工作区也不会越界。歌词只有一行，可优先译文，无译文回退原文；按可用宽度缩小至设置下限，仍超长使用段落省略，不手工截断 UTF-16 字符。输入按完整字素限制到2048个显示单元，避免异常巨大标签拖慢布局。

高度、间距、最小字号和译文选择持久化并即时同步。系统大字号会提高必要行高以容纳文字，不能超过屏幕可用高度；极小显示区域下以不裁切文字为先。独立外观面板开关不改变单行窗口；只有用户改变模式或字号等布局设置时才调整歌词窗口。退出单行恢复先前悬浮窗口。原生调整失败时回退到已应用模式，独立显示布局错误，不被保存成功回执清掉。

## 个性化与性能

主设置与外观面板共享同一不可变偏好、选项组件及IPC，不建立第二套歌曲/歌词/播放逻辑。原文和译文字号、文字/背景透明度、描边、跟随主题/自选颜色集中可调。主设置连续滑动300ms合并保存，离开设置时提交待保存值；失败可重试。

单行继续复用已有逐词绘制器。播放计时仅重绘缓存，不重新测量字号或重建文字布局。全透明且无悬停时不启用无用背景模糊。列表模式不再创建仅网格需要的O(n)索引表，网格的定位、重排语义不变。

## 检查边界

按用户要求，本轮不启动安装版或进行截图/人工视觉验收；执行真实 Flutter widget 布局、交互、异步和主题回归，静态检查、Rust及原生策略检查，再进行 Release 构建。测试环境不修改原始音乐、图片或已安装程序。

自动化通过不代表覆盖每一种第三方音乐接口响应、音频设备、全屏应用、DPI组合或长期性能；未测项目不标作“无bug”或“全局最优”。具体本轮最终结果记录在 `26.0.3-validation.md` 的最新章节。

发布脚本 `build_windows_release.ps1` 默认执行 `verify_interaction_regressions.ps1` 的交互、四语、主题、布局和隐藏渲染专项，失败就中止Release编译。现有Windows CI在构建前继续运行完整Flutter/Rust测试，并新增原生字体资源生命周期门禁；这次问题保留为长期回归用例，不只在本次手动检查。
