# 增量刷新曲库

设置 → 曲库与播放 → 刷新音乐库，提供「增量刷新」与「完整刷新」。管理音乐文件夹仍执行完整扫描。

- 增量刷新递归枚举已选根目录，以路径、文件大小和纳秒修改时间识别新增、删除及改动歌曲；未变化记录直接复用，保留原顺序和元数据。待重试的读取或需补全的分类字段仍可能重新读取。
- 完整刷新强制重新读取所有歌曲信息。两种模式都只读取音乐文件，不写标签、侧车歌词或文件名。
- 根目录单独保存，包括暂时没有歌曲的目录；后来新增的子目录也能发现。旧索引会在首次刷新补齐文件指纹。旧格式未保存的空根目录无法反推，应在管理文件夹中重新选择一次。
- 删除只基于成功枚举的目录。任一已选根目录失联、枚举失败或必要属性读取失败时，整轮扫描不提交；完整刷新也不会因此清空旧曲库。扫描期间正在读取的文件发生变化同样会中止提交。
- 标签解析暂时不能完成时，已有歌曲保留上次信息，新歌曲保留可用信息或文件名；标记为待重试并在完成提示中报告数量，不将其笼统判断为坏歌曲。
- 增量刷新只使新增、改动、删除及待重试歌曲的封面缓存失效；完整刷新清理封面缓存。冷启动的封面键也包含高精度时间与大小。联网曲目、歌单、播放引用和搜索索引仍按原有同步流程处理。
- 歌曲信息保存的原生写入与曲库同步，以及刷新的扫描与重载，共用一个操作门禁。忙时明确提示重试，不把旧歌曲对象排队到新曲库之后。刷新任务独立持有原生进度流；关闭或销毁观察视图不会提前放锁，也不会把取消 Dart 订阅误当作取消原生扫描。

判变不逐首计算音频内容哈希，以避免每次刷新都读取全部音频数据。如果外部程序改变内容却刻意保持文件大小和修改时间不变，请使用完整刷新。这不是实时目录监听，也不保证跨进程修改媒体文件的原子快照。

## 验证边界

仅使用合成文件、隔离索引和注入流；没有对真实用户曲库执行刷新或写入。

- Rust：16 项新增增量测试；全 Rust 为 60 通过、1 个有副作用的 opt-in 探针保持忽略。覆盖同秒时间差、时间倒退、大小变动、大小写改名、顺序保留、空目录、新子目录、删除、失败保留与旧格式补读。
- Flutter：两份新增专项共 38 项，连同分类持久化、封面缓存和元数据编辑相关回归共 62 项通过。四语 × 320/800 宽度 × 100%/200% 字号的刷新按钮矩阵通过。
- 屏障测试确认：观察者取消后仍完成扫描与重载；原生失败不调用重载；重载完成前仍拒绝并发元数据保存；失败最终释放门禁。
- 相关 Dart 文件静态分析无问题。没有新增 FRB API；打包时仍必须重建主程序 Rust 库和含新译文的歌词辅助程序。
