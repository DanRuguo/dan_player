# 26.0.3 统一歌单与旧合集迁移

“合集”与“歌单”只有一个可编辑入口和一套持久化数据。原合集不再是第二套列表。

## 保留什么

- 已有歌单的 ID、歌曲次序、嵌套关系不变；旧合集按来源次序追加到顶层。
- 合集名称、封面路径、创建/修改时间、所有歌曲路径和重复歌曲引用保留。
- 同名、重复来源 ID、缺少来源 ID 的合集分别保留，不按名称猜测去重。
- 音乐盘未连接、歌曲未被当前索引收录或联网元数据暂不可用时，仍保留引用；不会扫描后自动删除这些项。
- 总乐库的自定义排序仍使用自己的 `custom_audio_order.json`，不与歌单混排顺序混用。
- 原偏好记录与启动页索引保留；旧 `/collections` 路径进入同一歌单界面。新列表/网格选择单独保存，原合集布局作为兼容默认值。

## 文件与失败保护

沿用原应用数据目录，首次成功迁移将 `playlists.json` 升为版本 3 的 JSON 对象，包含 `playlists`、`migratedCollectionKeys` 和 `legacyCollectionsMigrated`。仍兼容读取旧歌单数组格式；软件版本号仍为 26.0.3。

- `collections.json` 与 `collections.json.bak` 只读保留，不改写、不删除。
- 真正合并前，若旧歌单主文件存在，另存 `playlists.before-collection-merge.json.bak`；若旧常规备份存在，另存 `playlists.before-collection-merge.previous.bak`。这两个快照只创建一次，后续保存不轮换它们。
- 正常保存使用临时文件及 `playlists.json.bak`。数据与迁移记录在同一快照中提交，失败后重试不重复导入；删除已迁移歌单后也不会从旧合集文件复活。
- 完整读取失败时先尝试完整备份；主文件与备份均不可用时保留原文件，显示错误并阻止新建/编辑/拖动/加入歌曲，修复文件后可在歌单页“重新读取”。不会用空歌单覆盖坏文件。
- 保存失败保留内存歌单并显示“重试保存”，刷新曲库不能用旧磁盘状态覆盖它。退出前应重试成功；未成功写盘的本轮编辑无法保证在进程关闭后保留。
- 短窗或大字号下，持久错误提示在独立的有界区域内滚动，重试按钮可用触摸或键盘到达，不挤掉歌曲列表；无错误时该区域不占高度。

只迁移歌单记录，不搬动、删除或修改音频和封面源文件。不应在新旧版本中同时编辑同一数据目录；旧版不能理解新的版本 3 对象。

若需要回退旧版，先完全退出新旧播放器，并另行复制备份整个应用数据目录，再将迁移前快照复制为旧版 `playlists.json`。不要删除原快照；迁移后新增的修改不包含在迁移前快照内。本轮开发和测试未读取或修改用户的真实歌单目录。

## 合并后的操作

- 歌单详情的封面移到标题左侧，宽窗放大到 112 个逻辑像素，窄窗为 72–88；名称、数量和操作按钮集中排布，面包屑不再承担小封面。短窗/大字号允许页头独立滚动，歌曲列表仍保留空间。此布局不修改封面原文件、歌曲次序或迁移记录。
- 顶部文字按钮与图标按钮统一实际绘制高度；常规至少 44 个逻辑像素，大字号时一起增高，保留悬停、按下和模式切换动画。
- 新建歌单时可同时选择名称、封面与歌曲，也可先创建空歌单再加子歌单。
- 右键、长按或项目菜单可改名、换封面、恢复默认封面、更改所选歌曲、移动及删除；在当前歌单内也可使用顶部“更多”菜单。“添加”集中提供新建子歌单和添加歌曲。
- “更改所选歌曲”只影响当前层，保留子歌单以及仍选歌曲的混排位置和 ID；缺失引用默认仍选中。同一歌曲的多个引用均保留，若只需删除其中一次，请使用该行菜单或按条目多选。
- 网格/列表切换不改变歌曲顺序。名称、歌手、专辑及歌曲数量等排序只影响显示与播放次序，作为各层独立偏好保存，不覆盖已有自定义顺序；中文沿用既有拼音排序。切回“自定义”后，可拖动右侧三个点或用 `Alt+↑/↓` 调序，短按三个点则打开菜单。
- 列表拖动使用连续挤位、回落和边缘自动滚动。向子歌单封面/名称区域停留约半秒，显示“松开移入”后释放；也可用菜单指定移动目标。所有移动均按条目 ID 操作，连续拖动不必等待上一次磁盘保存结束，失败提示和快照保护仍保留。
- 顺序播放按各层当前排序深度优先进入子歌单，子单结束后返回父级下一项；重复歌曲按具体出现位置定位。随机模式保留原有选择。
- 原“专辑”入口位于顶层歌单页的“更多”菜单；它不是可编辑歌单，不计入歌单数量。
