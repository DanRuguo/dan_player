## 本轮新增：Jamendo 限定来源模板

[可导入配置](examples/go-music-api-jamendo.json)连接用户自行部署的 go-music-api。默认地址 `http://127.0.0.1:8080/` 是本机服务占位地址，配置默认关闭；没有捆绑服务或新增公共代理依赖。

用途是只查询 Jamendo，不对所有平台发起聚合搜索。上游 [`handler/music.go`](https://github.com/guohuiyuan/go-music-api/blob/bacdfbe6cf6a5ba7331463d2039e3aac915c627f/handler/music.go) 的 `UnifiedSearch` 明确读取 `sources` 查询数组；当前传输层保留端点查询参数，因此 `api/v1/music/search?sources=jamendo` 可以直接使用。其他能力沿用上游现有歌词、封面和音频流代理。上游没有这套歌曲评论接口，模板不声明评论能力。

使用方式：

1. 在“设置 → 第三方 API”导入上述 JSON。
2. 将地址改成自己的 go-music-api 服务地址；服务按固定提交的上游说明自行部署。
3. 启用该配置，输入要查询的作品进行“测试”，按实测能力使用。没有实际部署服务时，连接失败属于预期。

声明式配置解析及 `sources=jamendo` 查询保留已在本机检查；未启动第三方服务，未声称 Jamendo 实时搜索、播放或下载已经联网验收。聚合 go-music-api 模式已存在，本轮不重复添加同类预设。

## 增强版网易云 API：发布前已完成适配

本节最初记录候选设计。26.0.4 发布前已新增 `netease-api-v1` 协议、设置预设并在本机运行上游服务完成固定 ID 实测；当前结果见 [接入与验证记录](26.0.4-api-release-additions.md)。

具体证据来自固定提交：

- [`module/search.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/d55d92cd0031d7c7746b7068faecd7ade1d354ac/module/search.js) 使用 `keywords`、`limit`、`offset`；通用 v1 使用 `q` 和 `tracks`，仅粘贴 `/search` 地址不能正常解析。
- [`module/lyric.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/d55d92cd0031d7c7746b7068faecd7ade1d354ac/module/lyric.js) 按平台 `id` 查询原始歌词响应；专用适配器已将 `lrc.lyric` / `tlyric.lyric` 映射为播放器的原文与翻译歌词。
- [`module/comment_music.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/d55d92cd0031d7c7746b7068faecd7ade1d354ac/module/comment_music.js) 使用 `offset` / `before`；[`module/comment_new.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/d55d92cd0031d7c7746b7068faecd7ade1d354ac/module/comment_new.js) 使用 `pageNo`、`pageSize`、`sortType`，时间排序还需要 `cursor`，不能映射成所有来源通用的“页码 + 热门/最新”假设。

当前独立 `netease-api-v1` 适配器已实现匿名搜索、歌词、元数据、明确的热门/最新评论及媒体解析。分页采用 `comment/music` / `comment/hot` 支持的有限偏移量，不宣称实现 `comment/new` 的游标协议。新增预设默认停用，用户需填写自己已部署的服务地址。

## LX 的可借鉴边界

已读 [`src/common/types/user_api.d.ts`](https://github.com/lyswhut/lx-music-desktop/blob/9c364b482e5621a1d38b50e8610d2fb974457e6e/src/common/types/user_api.d.ts) 和 [`src/main/modules/userApi/renderer/preload.js`](https://github.com/lyswhut/lx-music-desktop/blob/9c364b482e5621a1d38b50e8610d2fb974457e6e/src/main/modules/userApi/renderer/preload.js)：可借鉴来源明确声明动作和失败反馈的设计。Dan Player 继续使用自己的能力声明、独立曲目 ID 和取消/超时控制；本轮没有引入 LX 脚本加载器，也没有复制第三方账号、Cookie、媒体解密或绕过付费限制的实现。
